# 首页音乐与文案调整设计

日期：2026-06-03

## 目标

这次只处理首页的四个细节问题：

1. 音乐卡片需要支持站内直接播放，而不是只切换播放图标。
2. 首页三首歌需要按“天”整体轮换，同一天所有用户看到同一组歌。
3. 音乐卡片的米色卡不能再透出后层内容，三张卡都要是实底。
4. 首页主文案需要更柔和，去掉过于功能说明式的句子。

## 方案概览

推荐采用“第三方聚合音源 + 服务端每日歌单”的实现方式：

- 歌曲展示信息优先保留网易云来源语义。
- 真正的播放链接通过可直连的第三方接口获取。
- 如果网易云侧无法拿到可播链接，允许单首歌曲自动回退到其他音源。
- 首页前端只消费一个“当日三首歌”接口，不再依赖本地写死的三首歌数据。

这样能同时满足“站内可直接播放”“每天三首整体一起换”和“允许局部降级”这三个要求。

## 架构与组件

### 1. 首页歌单数据层

新增一个服务端歌曲提供模块，职责如下：

- 维护一个可轮换的候选歌单池。
- 根据当前日期生成稳定的“今日索引”。
- 从候选池中选出当天的 3 首歌。
- 为每首歌补齐展示信息和播放信息。

数据结构建议包含：

- `id`
- `title`
- `artist`
- `subtitle`
- `mood`
- `duration`
- `sourceLabel`
- `sourceUrl`
- `audioUrl`
- `fallbackAudioUrl`
- `isPlayable`
- `accent`
- `bars`

### 2. 首页接口层

保留现有 `GET /api/home/song-deck` 与 `POST /api/home/song-deck` 的交互形式，但改成服务端实时生成当日卡组：

- `GET` 返回当天的 3 首歌和默认前置卡片。
- `POST` 只负责卡片前后切换与选中逻辑，不再依赖固定常量数组。

这样可以尽量少改前端交互代码。

### 3. 音乐卡片播放层

首页音乐卡片增加真实 `audio` 控制：

- 前台维护一个隐藏的 `HTMLAudioElement`。
- 点击主卡片时播放或暂停当前歌曲。
- 切换到下一张卡片时，自动加载对应歌曲音源。
- 如果播放失败，先尝试 `fallbackAudioUrl`。
- 如果回退也失败，保留卡片展示并提示“当前音源暂不可用”。

### 4. 视觉层

卡片层叠保留，但避免内容穿透：

- 米色收据卡改成不透明暖米色底。
- 其他卡片也维持实底，不使用会透字的透明度。
- 后层卡片只通过位移、旋转、阴影体现层次，不依赖透明叠加。

## 数据流

1. 用户进入首页。
2. 前端请求 `/api/home/song-deck`。
3. 服务端根据当天日期选出固定 3 首歌。
4. 前端渲染三张卡，第一张为当前播放目标。
5. 用户点击播放时，前端读取当前卡片的 `audioUrl` 播放。
6. 用户拖动、滚轮或双击切卡时，前端切换当前曲目。
7. 如果音源失效，前端尝试备用音源；仍失败则展示不可播放状态。

## 文案调整

首页首屏文案调整为：

- 主标题：`给今天的心事，留一间安静发光的房间。`
- 说明文案：`从一件具体的小事写起，让情绪慢慢显影，也让你重新看见自己。`

以下文案删除，不再保留在首页首屏：

- `Realis / 返照帮助你记录具体事件，与 AI 对话式觉察情绪根源，并把洞察封存为未来能重新观看的记忆画廊。`

如果品牌总述仍需要保留，也应改成更短、更感性的版本，而不是功能罗列。

## 错误处理

- 第三方接口请求失败时，接口返回本地兜底歌单，保证首页不空。
- 单首歌曲缺少可播链接时，不影响另外两首展示。
- 播放失败时，前端显示温和提示，不打断首页其他交互。
- 当天歌单生成失败时，回退到内置默认三首歌。

## 测试与验证

需要覆盖以下验证点：

- 同一天重复请求接口，返回的是同一组 3 首歌。
- 跨天后接口返回新的 3 首歌。
- 点击主卡片可以真实播放与暂停。
- 切换卡片后能切到新的音源。
- 某首歌主音源失效时会尝试备用音源。
- 米色卡片不再透出后层文字。
- 首页两处文案完成替换。

## 范围边界

这次不处理：

- 用户个性化推荐。
- 完整的外部音乐搜索能力。
- 登录后按用户心情动态推歌。
- 首页整体结构重做。
