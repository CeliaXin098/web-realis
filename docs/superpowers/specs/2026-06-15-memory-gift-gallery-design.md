# 记忆礼物画廊重设计

日期：2026-06-15

## 目标

彻底替换现有“记忆画廊”页面。每次用户保存 AI 觉察时，系统根据本次觉察内容，遵循 `dear-skill` 的创意判断方式，生成并封存一份独特的情绪礼物。进入画廊后，导航栏下方只展示当前礼物的小世界；用户通过左右滑动穿行不同记忆。

画廊不是觉察记录列表，也不是固定模板换色。每条记忆应有自己的视觉隐喻、互动规则和情绪节奏。

## 已确认设计

### 画廊外壳

- 使用“沉浸舞台”方案。
- 保留站点上方导航栏。
- 导航栏下方由当前礼物全屏接管，不展示侧栏、卡片列表或常驻详情面板。
- 支持触控左右滑动、触控板横向滑动、鼠标拖动、键盘方向键和左右按钮切换。
- 首次进入时短暂显示“左右滑动查看下一份礼物”，随后淡出。
- 序号、切换按钮和入口默认低干扰；鼠标移动、触摸或键盘操作时短暂唤回。
- 切换礼物时使用横向舞台转场，但每份礼物内部的动画与交互保持独立。

### 觉察详情

- 右下角保留轻量“查看觉察”入口。
- 点击后以抽屉或浮层展示原始事件、AI 觉察总结、情绪标签、深层原因、模式、给未来的自己及疗愈建议。
- 关闭详情后回到礼物原来的互动状态。
- 详情层不能改变礼物本身的构图或缩小礼物舞台。

### 礼物生成时机

- 用户点击“保存到记忆画廊”时，同步生成礼物规格并与觉察记录一起保存。
- 礼物一旦生成即封存，后续打开画廊不会重新生成或随机变化。
- 保存接口只有在觉察记录与礼物规格都成功落库后才返回成功。
- 若创意生成失败，使用确定性的本地兜底生成器创建一份完整礼物规格，不能保存一个空画廊项目。

## Dear 创意规则

系统把用户自己视为礼物接收者。输入素材来自本次 AI 觉察，而不是要求用户再回答一轮问题。

每次生成必须从以下内容中提炼：

- `anchor`：这次觉察中最值得被看见的具体时刻。
- `return`：这份礼物带回给用户的新视角、重构或温柔提醒。
- `concept`：一个具有自身规则、能够被描述为具体事物的小世界。
- `interaction`：与当前情绪能量匹配的零负担或微交互。

创意不能只是复述总结、展示漂亮背景或把固定模板换色。礼物至少需要一个清楚的世界规则，例如：

- 擦开雨窗，才看见“这次刺痛真正来自哪里”。
- 被风吹散的句子最后聚成一条新的边界。
- 点击沉睡的花苞，让没有被看见的努力逐一开花。
- 拖直一张皱纸，显露给未来自己的那句话。

情绪较重时只允许零交互或微交互，不要求用户输入、回答或完成任务。

## 数据设计

在 `reflection_records` 增加非空 `gift_spec jsonb` 字段。旧记录通过迁移设为可空，并由读取时兜底生成器渲染；新保存记录必须包含完整规格。

`gift_spec` 采用版本化结构：

```ts
type GiftSpec = {
  version: 1;
  conceptFamily:
    | "transformation"
    | "interactive-object"
    | "narrative"
    | "data-viz"
    | "poetic-literary"
    | "borrowed-media";
  conceptTitle: string;
  anchor: string;
  returnMessage: string;
  world: "rain-window" | "bloom-garden" | "wind-words" | "light-beam" | "paper-release" | "memory-orbit";
  palette: {
    background: string;
    foreground: string;
    accent: string;
    glow: string;
  };
  textBlocks: Array<{
    role: "label" | "primary" | "secondary" | "whisper";
    text: string;
  }>;
  interaction: {
    type: "wipe" | "tap-bloom" | "scatter" | "drag-light" | "smooth-paper" | "orbit";
    instruction: string;
  };
  motion: {
    intensity: "quiet" | "gentle" | "bright";
    particleDensity: number;
  };
};
```

第一版使用一组高质量的可组合世界渲染器承载完全不同的概念。世界类型、文案、颜色、运动强度和交互规则由 AI 决定；画廊外壳不决定礼物内容。

## 生成架构

保存接口在写入记录前调用 `generateGiftSpec(reflectionInput)`：

1. 汇总事件、总结、情绪、深层原因、潜在需要、模式和给未来自己的话。
2. 使用结构化 AI 输出生成 `GiftSpec`，并用 Zod 严格校验。
3. 校验失败或 AI 不可用时，调用 `buildFallbackGiftSpec`。
4. 将觉察记录与 `gift_spec` 一次写入数据库。
5. E2E 模式使用固定的测试礼物规格，保证测试稳定。

礼物生成提示词采用 `dear-skill` 的关键约束：具体锚点、真实回赠、世界规则、低互动成本、避免诊断、避免泛泛鼓励。

## 前端组件

- `GiftGalleryStage`：管理当前索引、滑动切换、键盘导航、控制层显隐与详情层。
- `GiftWorld`：根据 `gift_spec.world` 选择独立渲染器。
- 世界渲染器：每个组件只负责一种物理隐喻和互动，不读取数据库记录详情。
- `ReflectionDetailSheet`：展示原始觉察信息，不参与礼物生成与渲染。
- `LegacyGiftAdapter`：为没有 `gift_spec` 的旧记录生成稳定的本地礼物规格。

所有世界必须：

- 覆盖导航栏下方完整可视区域。
- 桌面端和移动端均可用。
- 支持 `prefers-reduced-motion`。
- 可通过键盘操作，互动区域具有可访问标签。
- 不依赖远程图片或运行时重新调用 AI。

## 转场与状态

- 左右滑动距离或速度达到阈值时切换，否则回弹到当前礼物。
- 切换过程中锁定新的切换请求，避免索引连跳。
- 当前礼物卸载时清理计时器、指针监听和动画状态。
- 打开详情层时暂停礼物交互；关闭后恢复。
- 页面刷新后默认展示最新记忆。

## 空状态与错误

- 没有记录时仍使用沉浸式空舞台，展示一份安静的“尚未封存礼物”世界，并提供去 AI 觉察的入口。
- 未登录和未配置 Supabase 的页面保持现有权限提示逻辑，但视觉应简洁，不复用旧画廊布局。
- 单条礼物规格损坏时，只对该条使用本地兜底，不阻塞其他礼物。

## 验证标准

- 保存觉察后，返回记录包含有效 `gift_spec`。
- 刷新画廊后，同一条记录的礼物不变化。
- 多条记录可通过触控、拖动、滚轮横向动作、键盘和按钮左右切换。
- 导航栏下方没有旧画廊的卡片堆、详情面板和对话回看区域。
- “查看觉察”浮层能打开、关闭并展示当前记录内容。
- 至少六种世界渲染器具备明显不同的构图、交互和情绪表达。
- 移动端 375px 宽度、桌面端常见尺寸和减少动态效果模式均可正常使用。
- 单元测试覆盖礼物规格校验、兜底映射和旧记录适配；E2E 覆盖保存、进入画廊、切换和查看觉察。

## 非目标

- 第一版不生成并保存任意 HTML 文件，也不在浏览器运行 AI 生成代码。
- 第一版不提供礼物编辑器、重新生成按钮、公开分享链接或背景音乐。
- 第一版不迁移或删除旧觉察数据。
