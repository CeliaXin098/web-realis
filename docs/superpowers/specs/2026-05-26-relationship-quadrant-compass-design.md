# 象限式人际罗盘设计

## 背景

当前人际罗盘页已经能展示人物卡片、MBTI 手填、荣格八维推测、互动记录和沟通建议，但整体更像普通资料列表，缺少“关系地图”的视觉判断力。

新版将人际罗盘改成一张可点击的关系质量象限图。第一版先覆盖五类关系：朋友、同事、伴侣、家人、熟人。后续再扩展到客户、网友、前任、合作伙伴等更泛化的人际对象。

## 核心模型

### 坐标轴

- 横轴：关系健康度，越往右越健康。
- 纵轴：相处愉悦度，越往上越愉悦。

### 四个象限

- Q1：滋养关系。健康且愉悦，充满支持、松弛、互相看见。
- Q2：稳固但费力。健康度高，但相处不一定愉悦，可能责任感强、边界清楚但有距离。
- Q3：上头但消耗。愉悦度高，但健康度低，容易有情绪拉扯、讨好、依赖或隐性竞争。
- Q4：需要边界。健康度和愉悦度都低，需要降频、重新设边界或减少投入。

### 友谊层级的泛化表达

第一版把“友谊层级”泛化为“关系层级”：

- Tier 1：最亲近的人。
- Tier 2：重要且稳定的人。
- Tier 3：普通关系或低频联系。
- Tier 4：熟人、弱连接或仅场景性联系。

在图上用圆点大小、光晕强弱和边框层级表达。Tier 1 最大，Tier 4 最小。

## 关系模式标签

“10 种奇特友谊类型”在产品中不直接叫友谊，而叫“关系模式标签”，以便适配朋友、同事、伴侣、家人、熟人。

第一版标签：

- 不主动提问型
- 无法单独相处型
- 表演型关系
- 双重义务型
- 半伴侣型
- 历史型关系
- 非平行人生型
- 亦敌亦友型
- 社媒名人型
- 不平衡型

第一版可以在前端基于现有资料轻量推断并展示；后续由 AI 在保存觉察结果时写入更准确的标签。

## 页面结构

### 顶部区域

保留当前 Realis 的温润克制风格，但去掉工程感说明。顶部只负责建立页面语境：

- 标题：人际罗盘
- 简短说明：把重要关系放进象限图里，看见谁滋养你、谁消耗你，以及下一次如何相处。
- 统计：关系人数、关联事件数、已生成建议数。

### 主体布局

桌面端使用左右结构：

- 左侧：关系象限图。
- 右侧：选中人物详情。

移动端改为上下结构：

- 上方：可横向/纵向滑动的象限图。
- 下方：选中人物详情。

## 关系象限图

关系图是一张带柔和网格的二维坐标面，不做传统“罗盘”造型。

视觉表达：

- 四个象限用低饱和色块区分，不刺眼。
- 中央十字轴清晰但克制。
- 每个人是一个可点击圆点。
- 圆点颜色按关系类型区分：
  - 朋友：绿松/鼠尾草色
  - 同事：金棕色
  - 伴侣：陶土色
  - 家人：橄榄灰绿色
  - 熟人：米灰色
- 圆点大小表示 Tier。
- 圆点位置由 `health_score` 和 `joy_score` 决定。
- 悬停时显示昵称、关系类型、象限、Tier。
- 点击后右侧详情同步切换。

## 人物详情卡

右侧展示选中人物的关系画像：

- 昵称或称呼
- 关系类型
- Tier 层级
- 所在象限
- MBTI 手填入口
- 荣格八维推测
- 常见触发点
- 关系模式标签
- 关联互动事件
- AI 相处建议

详情卡不做“诊断口吻”，保持陪伴式表达，避免把人固定成标签。

## 后端与数据

### 现有基础

当前已有 `person_profiles`，并已经支持：

- `relationship_type`
- `nickname`
- `related_record_count`
- `common_triggers`
- `relationship_pattern_summary`
- `mbti_tendency`
- `jungian_functions`
- `closeness_score`
- `interaction_guide`

### 第一版新增字段

建议新增：

- `health_score integer not null default 3 check (health_score between 1 and 5)`
- `joy_score integer not null default 3 check (joy_score between 1 and 5)`
- `tier integer not null default 3 check (tier between 1 and 4)`
- `relation_mode_tags text[] not null default '{}'::text[]`

### 兼容策略

如果数据库尚未迁移，前端仍能运行：

- `health_score` 缺失时用关系模式和事件情绪轻量推断。
- `joy_score` 缺失时用情绪标签和相处描述轻量推断。
- `tier` 缺失时用 `closeness_score` 映射。
- `relation_mode_tags` 缺失时用现有文本内容兜底推断。

### API

`PATCH /api/person-profiles` 第一版继续负责保存 MBTI。新增字段可后续加入 PATCH 支持，但本轮优先保证展示和数据库兼容。

## 空状态

没有关系数据时，页面显示一张简化象限图：

- 中间提示“还没有关系点位”
- 引导用户去 AI 觉察页记录一次与他人有关的事件
- 给出 3 个示例点，帮助用户理解健康度、愉悦度和 Tier 的含义

## 测试与验证

实现后需要验证：

- `npm run typecheck`
- `npm run build`
- 人际罗盘页有数据时能展示象限图和右侧详情
- 没有数据时展示空状态
- MBTI 保存功能不回退
- E2E mock 数据不真实调用 AI，也不依赖真实 Supabase 数据

## 非目标

第一版不做：

- 拖拽人物点位并保存
- 完整 MBTI 测试
- 复杂 AI 重新评分流程
- 多人关系网络连线
- 付费或权限分层

这些可以在象限图稳定后作为后续版本推进。
